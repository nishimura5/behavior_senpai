# Behavior Senpai 1.7.0 リリースノート案

状態: dev170のリリース候補。2026-11-02時点で1.7.0の配布物・タグ・リリースは未公開。
この文書は公開前のレビュー用であり、配布完了の告知ではない。

比較対象は1.6系列のローカル `dev160`（`5a9133a`）。`dev170`の最終コードに先行するデータ保護修正と今回の修正を加えた、作業ツリーの実差分に基づく。
途中のコミットで追加後に削除された手検出パイプラインなどは、新機能として含めない。

## 1.6系列からの主な変更

- Feature copy画面を追加。テンプレートのPoints・Mix/Norm定義を使う再計算、対象シーン・memberの指定、Take/Part編集、動画時刻表示、PKLへのジャンプ、シーンのMP4出力に対応。
- Removeにtimestampに基づく間引きとスコア統計を追加。memberごとに間引き、同時刻のキーポイントを保持する。
- Mix/Normの選択行からCSV出力、描画範囲指定に対応。
- UMAPを子プロセスへ移し、Tk画面を応答可能に保つ。失敗時のコントロール復旧、計算中の画面破棄時のワーカー停止・一時ファイル削除に対応。
- Member編集にmean score表示と単一フレームmemberの削除対応、Member／Scene tableの動画移動操作などを改善。
- WholeBody133の鼻・口のキーポイント定義、および既定の特徴量計算を更新。

## データ保護・不具合修正

- Trackの座標とattrsの未保存状態を判定し、ディスクのTrackを使う操作や切り替え前に保存・破棄・キャンセルを確認する。保存失敗・キャンセル時は編集を保持する。
- Feature copy／Track listの変更がないダイアログ開閉ではTrackを再読み込みしない。
- Track上書きは一時ファイルへの書き出しが完了してから元ファイルを置き換える。
- Feature copyは対象ごとに既存.featを複製した一時HDF5へ計算・保存し、全処理成功後に確定する。Points定義の有無の両経路で失敗時の既存バイト列を保持し、無関係なHDF5グループも保持する。バッチ全体の一括トランザクションではない。
- Bandpass／Highpass／Lowpassは60Hz固定を廃止し、member・シーンごとのミリ秒timestampから実効周波数を求める。不規則時刻・欠測・短すぎる区間・Nyquist条件違反を理由付きで中止する。[時間軸の仕様](feature_filter_timeaxis.md)参照。
- Feature copyのシーン保存失敗時、単一・複数選択の各行のsceneとmemberを列名で正しく復元する。
- 描画範囲は`0-1`、`10.0-30.0`に加え、`-1-1`、`-180-180`、`-10--2`と空白付き入力を扱う。非有限値・逆転・同値の上下限は画面でエラーにする。空欄は自動範囲。
- Feature copyはランチャーのVideoCaptureを共有する。動画出力後には元の動画と表示位置へ戻し、Trackの再読み込みを伴わない。
- MP4出力のVideoWriterプロパティ指定を修正し、出力先を開けなかった場合は成功扱いにしない。
- UMAPのUTF-8ログをcp932コンソールにも安全に表示し、ログ出力の文字コードエラーで計算成功を失敗扱いにしない。

## 既知の制約・今回の対象外

- **公開阻害要因**: 新規Windows CPU環境ではVideoCaptureを1回だけ生成した場合でも、終了・GC時のアクセス違反（0xC0000005）が再現する。既存環境の49テストは成功したが、新規環境は49件中11件が子プロセスの異常終了で失敗した。原因・対処は未確定で、この候補の公開は保留する。[再現手順と検証結果](release_verification_1.7.0.md)参照。
- Trackは引き続きPKL。TrackのHDF5化や汎用リサンプリングは含まない。
- キーポイント定義の選択は依然としてモデル名と組み込みTOMLの対応に依存する。未知のモデル名や独自のキーポイント構成をすべての画面で自動解決するものではない。
- DLCの.h5インポートはあるが、生成される`src/keypoint/deeplabcut.toml`は共有ファイルで、異なるDLC定義をインポートすると上書きされる。Trackごとに定義を埋め込む対応はない。一般のDLC構成に対して、肩・肘などの名前を前提とする既定特徴量計算が動くとは限らない。実DLCファイルを使う導入先確認が必要。
- フィルターは各シーン内で隣接時刻間隔の中央値から1%（丸め誤差を除く）以内の揺れだけを許容する。欠測の連結や補間をしない。30→20fpsなど不等間隔になる間引き結果はフィルターできない場合がある。間引き自体にはアンチエイリアス処理がない。
- この環境ではVideoCaptureを1プロセスにつき1回だけ生成する制約を維持する。
- Windows CUDA導入、各AIモデルの重み取得・推論品質、macOS、配布用EXE／ZIPでの起動は別途確認が必要。合成動画・実ファイルを使う自動GUIテストを、実利用者による受け入れ確認の代わりにはしない。
